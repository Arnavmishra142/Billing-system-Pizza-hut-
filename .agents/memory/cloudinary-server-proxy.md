# Cloudinary Upload Pattern

## The rule
API Key and API Secret must never reach the browser. Uploads use Cloudinary's unsigned
upload preset (no signing needed). Deletes go through the Express server proxy.

**Why:** GitHub Pages and Firebase Hosting are static hosts — no Node.js server.
A server-proxy-only approach breaks on those hosts. Unsigned upload presets are
Cloudinary's intended solution for browser-side uploads.

## How uploads work (browser → Cloudinary directly)
- Browser posts `multipart/form-data` to `https://api.cloudinary.com/v1_1/{cloud}/image/upload`
- Body fields: `file` (the image), `upload_preset` ('pizza_menu_upload')
- `cloud_name` and `upload_preset` come from `js/cloudinary-public.js` (ES module import)
- No API Key or API Secret used — unsigned preset allows upload without signing
- Returns `{ secure_url, public_id }` — stored in Firestore as `imageUrl`

## How deletes work (via server proxy, best-effort)
- `deleteMenuImage(publicId)` sends `POST /api/delete-menu-image` with `{ publicId }`
- Server calls `cloudinary.uploader.destroy(publicId)` using API Secret (server-side only)
- On static hosts: `fetch` fails silently — delete is skipped, image orphaned (acceptable)

## Credentials
- `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` → Replit Secrets → `server.js` only
- `CLOUDINARY_CLOUD_NAME` also exported in `js/cloudinary-public.js` (committed, safe — appears in CDN URLs)
- `CLOUDINARY_UPLOAD_PRESET = 'pizza_menu_upload'` — committed constant, not a secret

## Key files
- `js/cloudinary-public.js` — committed (not git-ignored), regenerated by server.js at startup
- `js/cloudinary-upload.js` — browser service: `uploadMenuImage()`, `deleteMenuImage()`, `extractCloudinaryPublicId()`
- `server.js` — creates upload preset idempotently at startup; holds API Secret for delete endpoint

## Upload preset creation
`cloudinary.api.create_upload_preset({ name, unsigned: true, folder: 'menu-images', ... })`
Run automatically at server startup. Idempotent — "already exists" error is caught and ignored.
Preset enforces: folder='menu-images', allowed_formats, max_file_size=10MB.

## GitHub Pages deployment
After ANY change to `js/cloudinary-upload.js` or `js/cloudinary-public.js`:
- Bump sw.js cache version
- `git push` so GitHub Pages picks up the new files
